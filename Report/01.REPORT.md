## 1. 개요

본 보고서는 MagicSquare_xx 프로젝트 **구현·설계 이전** 단계에서 수행한 **Mom Test 인터뷰(STEP 1)** 결과를 정리한다.

Mom Test의 핵심 규칙:

| 규칙 | 요지 |

## 2. Mom Test 워크북

### 2.1 페르소나

**4×4 부분 마방진을 손으로/코드로 다루는 학습자**

- 4교시 실습 맥락: 4×4 격자, 숫자 1~16, 빈칸(`?`) 2개, 마법 합 34
- 손 풀이·코드 구현·과제 제출을 **번갈아** 경험할 수 있는 역할
- ECB·TDD 등 **설계 방법**을 배우는 단계에 있음

### 2.2 인터뷰 답변 (과거 사실)

> **수집 상태: 부분 수집** — 과거 행동·시간·불편 1건 추가. 첫 10분 세부·포기 지점은 미수집.

| # | 내용 | Mom Test 적합 |
|---|------|:---:|
| 1 | *“나는 [페르소나: 4×4 부분 마방진을 손으로/코드로 다루는 학습자] 역할이야.”* | △ 역할 선언 |
| 2 | “마지막으로 ~했을 때” 질문에 **4교시 실습 슬라이드**(빈칸 2개, 합=34, ECB·Solver·GridUI) 제출 | ❌ 과제·설계 자료 |
| 3 | 슬라이드 실습 목표: *“ECB 분류 완성 + 문제인식(실패 조건) 3가지 이상 도출”* | ❌ 솔루션·목표 |
| 4 | *“**지난번에 빈칸 2개 넣었다가 34가 안 맞아서 20분 헤맸다.**”* | ✅ 과거·구체·본인 행동 |

**추궁(미응답):** *“그때 첫 10분 동안 정확히 뭘 했나요?”*

### 2.3 표면 문제 (금지 — 솔루션 섞인 문장)

인터뷰·슬라이드에서 **기록만** 하고, **문제 정의로 쓰지 않음**.

| ❌ 표면 문제 | 유형 |
|---|---|
| “4×4 부분 마방진을 **완성하는 프로그램**을 만든다.” | 제품 정의 |
| “빈칸 2개를 찾아 **Solver로 채우는 앱**을 만든다.” | 기능·솔루션 |
| “**ECB로** Validator·MissingFinder·GridUI를 **구현**한다.” | 아키텍처 |
| “**TDD로** 마방진 **솔버**를 짠다.” | 개발 방법 |

슬라이드에 포함된 솔루션 요소:

- **Entity:** `MagicSquare`, `Cell`, `SolveResult`
- **Control:** `SquareValidator`, `MissingFinder`, `Solver`
- **Boundary:** `GridUI`, `InputHandler`, `ResultDisplay`

### 2.4 진짜 문제 (한 문장)

**부분적으로 채워진 4×4 격자가 규칙을 만족하는지, 손이든 코드든 같은 기준으로 빠짐없이 판정하고 다시 확인할 때마다 시간과 확신이 계속 깎인다.**

| 축 | 내용 |
|---|---|
| **불편** | 빈칸 2개 채웠는데 **합 34가 안 맞음** → 맞는지 **확신** 불가 |
| **비용** | **20분** 헤맴 (재확인·시행착오) |
| **판정** | 행·열·대각·중복 등 **어느 줄이 틀렸는지** 바로 알기 어려움 |
| **재현** | 손·코드·매번 **같은 기준**으로 검증하기 어려움 |

## 3. 인터뷰 진행 기록

### 3.1 질문 1

> **4×4 마방진인데 칸이 일부만 채워져 있던 걸, 마지막으로 다룬 게 언제였나요? 그때 처음부터 끝까지 어떻게 진행했는지 말해 주세요.**

**응답:** 4.1 Magic Square 프로젝트 소개 슬라이드(이미지) 공유.

### 3.2 추궁 및 보강 답변

> **그때 첫 10분 동안 정확히 뭘 했나요?**

**응답(보강):** *“지난번에 빈칸 2개 넣었다가 34가 안 맞아서 20분 헤맸다.”*

| 항목 | 판정 |
|------|------|
| 과거 사실 | ✅ “지난번에” |
| 구체적 | ✅ 빈칸 2개, 합 34, **20분** |
| 본인 행동 | ✅ 직접 숫자 넣어 시도 |
| 솔루션 섞임 | ✅ 없음 |

### 3.3 멘토 평가 (슬라이드 응답)

| 항목 | 판정 |
|------|------|
| 과거 사실 | ❌ 없음 |
| 구체적 | ❌ 과제 설명 수준 |
| 본인 행동 | ❌ “내가 그때 뭘 했는지” 누락 |
| 솔루션 섞임 | ⚠️ ECB·Solver·GridUI 포함 |

### 3.4 Mom Test 증거 3줄 (응답에서 인용)

1. *“**지난번에 빈칸 2개 넣었다가 34가 안 맞아서 20분 헤맸다.**”*
2. *“나는 **[페르소나: 4×4 부분 마방진을 손으로/코드로 다루는 학습자]** 역할이야.”*
3. *“마지막으로 ~했을 때”* 질문에 **과거 행동 대신** — 4교시 실습 슬라이드(빈칸 2개 `?`, 합=34)를 **먼저** 제출 *(Mom Test 실패 사례)*.

## 4. 진짜 문제 vs 표면 문제 대비

```
[표면]  "4×4 마방진 완성 프로그램을 만든다"
           ↓  (솔루션·기능·아키텍처가 먼저)
[진짜]  "부분 채워진 격자를 같은 기준으로 빠짐없이 판정·재현하기 어렵다"
           ↓  (불편·비용·판정·재현)
[다음]  STEP 2 — 계약·Invariant·실패 조건 도출 (구현 아님)
```

## 5. MagicSquare_xx 후속 단계 연결

| 진짜 문제 축 | 후속 설계·구현 힌트 (본 보고서 범위 밖) |
|---|---|
| 판정·확신 | `is_magic_square` — 명시적 I/O·오류 코드 |
| 부분 채워진 보드 | 빈칸 2개 계약, `find_blank_coords`, `solution` |

| 책임 분리 | ECB — Validator(판정) vs Solver(탐색) 분리 |
