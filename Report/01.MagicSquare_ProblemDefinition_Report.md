## STEP 1 — Observation (관찰)

### 1.1 지금 풀려는 상황

- **학습자**가 4×4 격자에 1~16을 한 칸씩 배치하고, **행·열·대각 10선**의 합이 모두 **34**가 되도록 **부분적으로 채워진 보드**를 다루고 있다.
- 빈칸은 **`0` 두 칸**이며, 손 풀이·코드·과제 제출을 **번갈아** 경험한다.
- “무엇이 맞고 틀렸는지”를 **같은 기준으로 빠짐없이** 판정하기 어렵다는 **과거 경험**(20분 헤맴)이 있다.

### 1.2 왜 4×4인가

- 3×3 입문 대비 **탐색·검증 부담**이 한 단계 커지고, 16칸·**10선**은 **눈·손 검산 누락**이 잘 생긴다.
- UI·데모·자동화 모두 **한눈에 올리기 좋은** 크기이면서, 규칙은 **명시적 계약**으로 고정하기에 적합하다.

### 1.3 맥락

- **학습:** 배열, 제약, 판정 vs 탐색 분리, Test Loop(TDD).
- **시스템 비유:** “규칙을 만족하는 상태를 **판정**하고, 필요 시 **탐색**하는 모듈”의 축소판.

## STEP 2 — Mom Test (문제 인식)

### 2.1 페르소나

**4×4 격자, 빈칸 2개(`0`), 1~16, 합 34 맞추는 학습자**

### 2.2 Mom Test 증거 (과거 사실)

| # | 인용·사실 | 적합 |
|---|-----------|:----:|
| 1 | *“**지난번에 빈칸 2개 넣었다가 34가 안 맞아서 20분 헤맸다.**”* | ✅ |
| 2 | *“나는 4×4 부분 마방진을 손으로/코드로 다루는 학습자”* | △ |
| 3 | “마지막으로 ~” 질문에 **슬라이드(ECB·Solver)** 먼저 제출 | ❌ (기록만) |

**미수집:** 20분 동안 **행만/대각 포함** 등 **첫 10분 행동**, 최종 **포기·완료** 여부.

### 2.3 Mom Test 채점 (자체 점검)

| 체크 | 결과 |
|------|:----:|
| 미래 가정 없음 | ☑ |
| 과거·시간·실수 구체성 | △ (1건) |
| 진짜 문제에 솔루션名 없음 | ☑ |
| 표면 vs 진짜 분리 | ☑ |
| 도메인(4×4, 10선, 34, 빈칸 2) | △ |

**점수: 7 / 10**

## STEP 3 — 표면 문제 vs 진짜 문제

### 3.1 표면 문제 (잘못된 정의 — 이번에 하지 않음)

| ❌ 표면 문제 | 유형 |
|---|---|
| “4×4 부분 마방진 **완성 프로그램**을 만든다.” | 제품 |
| “빈칸 2개 **Solver 앱**.” | 기능 |
| “**ECB** Validator·MissingFinder·GridUI **구현**.” | 아키텍처 |
| “**TDD 솔버**.” | 방법론 = 목표 |

**오류:** “만든다”만 남기면 **판정·재현·회귀**가 뒤로 밀린다.

### 3.2 진짜 문제 (한 문장)

**부분적으로 채워진 4×4 격자가 규칙(10선 합 34, 1~16, 빈칸 2)을 만족하는지, 손이든 코드든 같은 기준으로 빠짐없이 판정하고 다시 확인할 때마다 시간과 확신이 계속 깎인다.**

| 축 | Mom Test 연결 |
|---|---|
| 불편 | 합 34 **불일치** → 확신 없음 |
| 비용 | **20분** 헤맴 |
| 판정 | **10선** 중 **어디**가 틀렸는지 모름 |
| 재현 | 매번 **다른 기준**으로 확인 |

### 3.3 개선된 문제 정의 (정확에 가까운 정의)

**“4×4·빈칸 2(`0`)·1~16·10선 합 34에 대해, ‘규칙 만족 / 위반 / 위반 Rule ID’를 **명시된 계약**으로 **반복 판정**할 수 있어야 하며, 그 판정은 **Test Loop**로 **회귀 보호**되어야 한다.”**

## STEP 4 — 핵심 Invariant

| ID | 불변 | 설명 |
|----|------|------|
| **INV-01** | 크기 | 격자 **4×4** |
| **INV-02** | 빈칸 | **`0` 정확히 2개** |
| **INV-03** | 치역 | 비빈칸 **1~16**, **중복 없음** (완성 시 1~16 순열) |
| **INV-04** | 10선 | **행 4 + 열 4 + 주대각 2** = **10선**, 각 합 **34** (완성·판정 대상) |
| **INV-05** | 판정 | 실패 시 **어느 Rule/선** 위반인지 **구분 가능** |
| **INV-06** | 재현 | 동일 Input → 동일 Output (Test Loop로 고정) |

---

## STEP 5 — 세션 3 워크북

### 5.1 주제 (한 문장)

**빈칸 2개가 남은 4×4 보드가 10선·34 규칙을 지키는지, Rule·Command를 고정하고 Test Loop로 판정을 되돌릴 수 없게 만든다.**

### 5.2 R-G-I-O

| | 내용 |
|---|---|
| **Role** | 4×4 부분 마방진 **학습자** — 틀릴 때 **20분** 재확인 |
| **Goal** | **판정 기준 고정** — 같은 보드 → 같은 결과, 위반 **식별** |
| **Input** | `int[4][4]`, `0`=빈칸 2개, 그 외 1~16 |
| **Output** | `{ ok \| fail, violated_rules[] }` *(해 채우기·GUI 아님)* |

### 5.3 성공 기준 (Mom Test 연결)

| ID | 기준 | 증거 |
|----|------|------|
| **SC-1** | 고정 픽스처 **수 초 이내** 판정 | 20분 헤맴 → **1회 명확 판정** |
| **SC-2** | **10선·빈칸 2·중복** 누락 없이 검사 | 행만 맞고 통과 **금지** |
| **SC-3** | Refactor 후에도 **동일 Input→Output** | 재확인·헤맴 → **재현 계약** |

### 5.4 8계층 — 세션 3에서 만드는 것

| 계층 | 세션 3 | 산출 |
|------|:------:|------|
| **Rule** | ✅ | INV-01~06, 실패 조건 |
| **Command** | ✅ | `validate_board`, `find_blank_coords`(선택) |
| **(Skill)** | △ | Rule↔테스트 1:1, “그건 나중” 범위 유지 |
| **Test Loop** | ✅ | Red → Green → Refactor, `tests/test_validate_board.py` |
| Entity / Boundary / UI / Solver | ❌ | 후속 세션 |

## STEP 6 — 훈련하려는 사고

1. **명세 = Rule** — “34 맞추기”가 아니라 **10선·빈칸 2·순열**을 **문장·테스트**로 고정.
2. **판정 vs 탐색 분리** — 이번 세션은 **판정(Command)** 만.
3. **I/O = 계약** — Red/Green이 **의미**를 갖게.
4. **Mom Test → PRD** — 표면 문제(앱·솔버)를 **범위 밖**으로 명시.
